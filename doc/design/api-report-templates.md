# 可复现报表模板

Status: 模板入口已部署并通过单城市/单日端到端验收；真实全量统计受上游资源限制，见任务记录。

## 使用方式

管理员在公共报表选择「套用模板」→「模板一」→已适配的数据源→生成报表。
模板一沿用现有浅色报表工作区，不生成 PPT。模板、字段映射与报表实例分离；同模板版本和数据源重复套用返回已有实例，不覆盖管理员编辑，也不覆盖旧报表。

## 接口与持久化

- `GET /api/reports/templates`：仅管理员，返回模板目录、版本与兼容 API。
- `POST /api/reports/templates/apply`：仅管理员，参数 `template_id`、`source_id`，返回已创建或已有的报表定义。
- 普通用户继续使用公共报表的聚合查询、精确 DUID 查询；不可管理模板、数据源或浏览全量明细。
- `POST /api/reports/:id/run?range=7d&city=北京市`：管理员手动刷新使用页面当前范围与城市。定时默认只查询最新一天。失败不删除其他筛选的有效缓存。
- `visualization.template` 保存模板 ID、版本、渲染器、字段适配标识及动态日期策略。模板配置来自 `internal/service/report_templates/template-1.json`，随二进制嵌入。
- 迁移 083 增加模板实例唯一索引，以及 `report_template_analytics_cache` 聚合缓存表。缓存按报表配置、数据源版本、日期和城市隔离，保存查询时间、真实数据日、缺失日和查询 ID；有效期 10 分钟，手动生成成功后覆盖对应缓存。
- 模板二、三须注册独立 ID 与对应渲染支持；模板一渲染器行为有破坏性变化时必须升版。当前不承诺任意数据源自动适配。

## V1.2 口径

`dt` 为标签快照日，默认取北京时间昨天，并非订单发生日。使用 `ps_score`、`price_score`、`coupon_score`、`time_score`，等级保留上游实际返回的所有档位（含中低、中高），不截成三档。已有得分包含 PRIOR 先验；订单指标为 `order_cnt_180d` 标签记录计数汇总，不是每日真实订单量或 GMV。

用户数采用 COUNT DISTINCT，不得因大查询失败改成 COUNT。均分按对应非空样本数加权，空分不变成 0；缺失日期不补造曲线。源表应保证同 DUID/快照日单一标签；若重复且标签冲突，需先在上游明确唯一版本，否则分组用户数和订单汇总不具备一致用户口径。

资源不足返回 HTTP 422 / 42260 的脱敏提示，不自动重试巨量扫描，不将明细首页分布当全量统计。当前实际测试：单日全量去重超出 ClickHouse 8 GiB 限额，北京七天多指标查询触发30秒估算时限；COUNT 能返回但不能替代去重用户数。V1.2 可选择近1天。待上游预聚合或有界分批方案后再验收全部城市曲线。超过1000个聚合分组会拒绝结果，不缓存被截断的统计。缺少前一日时 `daily_growth_available=false`，前端隐藏该日日增量；首个观察日仅记为基准0。管理员非日期固定过滤与页面筛选取交集，V1.2 用原始日值绘图而非对空分补零拟合。

## 复现材料

模板 JSON 与该版本代码构成可执行模板，现有归档目录仅作备份，不含凭据，也不是运行时模板入口。签名仍从既有服务端配置读取，不复制到模板中。
