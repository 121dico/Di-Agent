# 报表持久预计算

## 用户确认

初始化和每日生成可以慢；日常切换城市、订单笔数、等级必须快。部署线上，长期记忆记录于根 AGENTS.md。

## 实现范围

- V1.2 主报表：按 dt 与城市预生成全量、已赋分、有订单分布，以及 all、1..10、gt10 十二档人数分布。
- 保存城市级汇总（非用户明细）及调用过程；复用 PostgreSQL analytics cache 的 prepared 独立命名空间，永久读取，不依赖10分钟TTL。
- 全量统计沿用既有 dt+duid 唯一粒度契约；订单档位以全城市等级合计对独立 COUNT DISTINCT 总量验证可加性，拒绝不守恒结果。
- 各日全部查询分页完整、字段授权和计数通过后，单行UPSERT原子发布；旧版本在失败时保留。配置/字段契约变更隔离旧结果。
- 启动补历史、每日10点刷新最新日，手动生成提交后台任务。顺序查询、分页上限100000，不发大量并行上游查询。
- 普通查询不触发上游；未准备好明确返回初始化状态。前端一次获得当前城市全部订单档位，切换档位/等级无网络请求；城市读取本地数据库。
- 场站独立验证、用户明细/精确DUID调查仍按原契约，不把身份查询伪装为预计算。

## 验收

公开 QueryAnalytics/QueryOrderCohort 在上游不可用时仍返回已发布北京一笔极高人群；城市别名、多城合并、缺失日期、字段撤权、分页重复与分母一致性回归。前端预计算路径不得发出 order-cohort 请求。上线后实测本地汇总响应；未完成初始快照前不得声称达标。
