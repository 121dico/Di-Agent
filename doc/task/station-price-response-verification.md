# 计划提价前后固定人群核验

## 范围

用户要求验证高/极高价敏消费行为，并将用户查询、数据明细、运行记录放在报表最后。
本轮先执行真实 API 的只读核验，保留可复跑脚本，不变更价敏标签，不增加未经验证的因果结论。

## 方法

- 数据源：station_price_sensitive_test_detail，身份仅服务器内存保留，输出仅汇总。
- 每站使用唯一 raise_dt 与正 planned_delta；多组/缺失配置不猜测。
- 分别比较 [T-7,T-1] 对 [T,T+6]、[T-14,T-1] 对 [T,T+13]，日期不足则跳过。
- 固定提价前有 MATCHED/private 有效 DUID 消费的用户，以窗口内最后一次此类消费的等级分组。并非统一T-1标签快照。
- 固定用户后统计前后所有订单，不再筛除提价后标签变化/缺失者；未回访者后期订单计0，新用户不混入。
- 每站去重，跨站汇总为用户-场站对，不能声称全局去重用户。
- 无实际支付、电量、周边价格或未提价对照，不能计算价格弹性、判定转向便宜站、证明提价因果。
- 入组条件要求前期消费，天然存在回归均值/选择偏差；前后下降不等于提价造成下降。高低等级间还受消费频次和站点构成影响。
