# V1.2 三块人群报表

## 范围
现有 V1.2 报表同页展示全量人群、有订单人群、每日新增，保留既有样式、城市和快照范围筛选、权限及缓存。旧报告不变，不修改 Hive 产表任务。

## 已接入
- 全量：单个最新返回快照的去重人数、已赋分人数、等级分布，未赋分补充为单独类别，不跨快照累加。
- 有订单：同样筛选条件追加 `ps_conf > 0`，按 dt/ps_level 真实去重聚合，人数及占全量比例；不是 `ps_type=ORDER`，也不是当天活跃用户。
- API 增加可选 `order_cohort: {user_count, share, distribution}`；查询权限在读缓存前验证，缓存版本更新，防止旧缓存被误解为0。

## 尚待上游支持
每日首次标签用户、每日订单用户、每日去重订单量、各新增人群的当日价敏分布明确显示待接入。当前快照没有首次日期与逐日订单字段，应用不下载亿级明细或跨源拼接，不将 ps_update_dt、相邻人数净变化、滚动订单差值冒充新增。

## 验证
### 2026-09-10：恢复 dt 历史接入
- 用户明确以标签快照 dt 为横坐标；目录实查返回 7 月 28 日至 9 月 9 日连续 44 天。新增认证后的 `range=dates` 目录读取，保留源表字段契约、已有条件与城市权限。
- V1.2 默认全部 dt 历史；最新日优先逐日聚合并显示进度，失败日期保留断点，不吞掉成功日期。概览沿用最新成功快照，人数不跨日期累加。
- 三张历史图：全量/正置信度人群规模、全量每日价敏分布、正置信度每日价敏分布；图例显隐和 hover 沿用模板一。真实订单日新增独立说明。
- 全城市 COUNT DISTINCT 会超上游内存；按用户提供 SQL 的 `(dt,duid)` 唯一粒度契约用 COUNT(duid)，明确标注未做全量唯一性校验。源表若违背唯一粒度，需上游修复或预聚合，不能将该计数当作独立验证过的去重结果。
- 历史查询仍通过服务端 API 和现有 10 分钟缓存，不把签名下发前端。手动生成刷新最新快照后重载选定历史。

公共 QueryAnalytics 回归：严格正置信度、真实0、分页截断拒绝、已有筛选及缓存；页面展示/空值回归。线上用户路径与容量限制在交付时补充。
