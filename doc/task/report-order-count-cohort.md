# 有订单人群按笔数筛选

## 功能
V1.2 价敏分布对比中保留全量人群，右侧支持全部有订单、精确1至10笔、超过10笔。服务端按所选单日、城市及保存的条件查询实际去重人数，分级合计与独立总数核对。图例和表格以当前组人数作为百分比分母。

订单字段为 `order_cnt_180d`，含义是标签最近更新时的订单数；不能用最多10笔的 `ps_order_cnt` 替代。全部有订单使用 `ps_conf > 0 AND duid > 0`，不额外剔除订单数字段未知的用户。

## 接口
`GET /api/reports/:id/order-cohort?date=YYYY-MM-DD&orders=all|1..10|gt10&city=城市`

复用已登录用户的报表查看权限。只返回聚合，凭据和DUID明细不下发。
响应沿用 analytics 结构，使用 `data_date`、`fetched_at`、`cached`、`counting_basis`、`order_cohort.user_count/distribution`；不使用其余总览字段。

## 性能与失败
独立10分钟持久化缓存；切换仅查当前快照，不重扫历史日期。配置或字段契约变化隔离缓存，权限撤销先验证。失败展示重试，不显示旧组人数或虚构零值。真正空人群会额外检查源快照存在。

## 验证
新增后端公共查询回归、前端筛选/过期响应回归与显式启用的真实源集成测试。现有全套中三项历史失败（前端首日NaN预期、旧布局顺序预期、后端站点路径403/404预期）不属于本次改动。
